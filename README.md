# 元素领域 · Ez Element

单店、私教与团课、线下收款的原生微信小程序。主色黄色与灰色。

当前为 **开发中的首个业务增量**，包含原生页面、后端事务业务及本地联动演示，不是已上线的运营系统。账号尚未申请，云环境没有开通。

## 目录

- `prototype/`：已确认的浏览器原型，仍可在 4173 端口查看。
- `miniprogram/`：原生 WXML / WXSS / TypeScript，小程序正式实现的起点。
- `server/`：业务服务、CloudBase 数据库适配器、可信微信身份云函数入口。
- `cloudfunctions/api/`：构建产物，供后续云环境部署；没有部署。

## 本地运行

```powershell
npm ci
npm run check
npm run dev:demo
```

`dev:demo` 仅监听 `127.0.0.1:4174`，每次启动创建未来七天的演示场次；重启清空演示预约。所有演示身份都是虚构的，只供开发工具模拟器使用，不能在手机上把 `127.0.0.1` 当作电脑地址。

项目配置使用用户选定的现有接口测试号（AppID 末尾 `245050`），客户端 `config.ts` 明确为 `demo` 模式。测试号仅用于本地调试，不支持云开发。WXML/WXSS 官方编译通过；Nightly 模拟器已验证三端渲染、七天选日期、私教预约冻结与教练名单联动。基础库固定为 3.17.4，具体证据见验证记录与 `reports/` 截图。

页面演示：学员选择日期/教练/时段 → 选择适用课包并预约；切到教练可看同一笔预约；管理员可创建团课、审核与线下开卡。结课按钮只在真实系统时间到达课程结束后出现；没有绕过时间规则的演示后门。

## 接入真实云环境

1. 获取真实小程序 AppID，并确认 CloudBase 国内/国际站点、环境归属和完整环境 ID；需支持文档数据库且绑定该小程序的环境。
2. 确认开发/正式环境分离；按 `database/manifest.json` 显式创建集合、索引并设置客户端读写均拒绝。运行时写入不会自动建集合。
3. 在云函数配置中设置 `EZ_ENV_ID`、`EZ_APP_ID`。客户端配置切为 `mode: 'cloud'` 并设置真实环境；`project.config.json` 改为真实 AppID，开启 `urlCheck`。
4. `npm run build:production` 会拒绝游客 AppID、本地演示模式、空环境或关闭域名校验的配置。`npm run build` 只生成开发产物。
5. 以 Event Function 部署 `cloudfunctions/api`，限定所需的小程序调用权限，不启用匿名 HTTP 网关。函数根目录是 `cloudfunctions/`。
6. 门店负责人先从小程序提交资料；由环境所有者核对本人后，在云数据库给该用户赋予 `admin` 和 `active`。教练同理由可信管理操作赋权；当前不开放客户端自助提权或凭手机号接管用户。邀请绑定界面留待后续实现。
7. 完成真实 SDK 事务、并发、权限和真机测试后才能进入试运营。

## 已实现的关键约束

- 微信身份来自 `getWXContext()`，客户端传入的用户 ID/角色不能替代鉴权。
- 所有业务修改通过服务端事务；名额、余额、预约、流水、站内消息和幂等记录一起提交。
- 教练/场地排课与学员预约使用日程文档进行冲突检查；区间为左闭右开。
- 购买、冻结、释放、消课记录独立保留；取消再预约生成新记录。
- 金额为整数分，禁止负数；私教课包必须指定可用教练。
- 自动化测试使用内存事务适配器，并不证明真实云端的锁冲突与网络重试行为。

## 当前限制

- 整场停课、改期、出勤冲正/退款、延期、角色邀请、设置页面、分页导出、订阅消息和定时提醒尚未实现。
- 工作台暂为有界查询（一般 200 条、单场名单 100 条），不能用于全量对账；正式运营前必须拆分分页查询及按日期的服务端过滤。
- 当前私教可约时段按具体日期逐条发布；跨日批量复制和编辑待补。规则采用方案中的默认值，取消期限等在运营前需确认。
- `npm audit` 检测到官方 SDK 间接依赖风险（见验证记录）；发布前需处理、升级或完成适用性评估，不能仅靠本地用例通过判定可上线。
