## 换电脑后的第一轮操作

1. 安装 Node.js（建议当前 LTS）和微信开发者工具 Nightly，登录具有该小程序开发权限的微信账号。
2. 拉取准确分支并核对提交：

   ```bash
   git clone --branch codex/ez-element-initial https://github.com/dreamrose1108-rose/ez-element.git
   cd ez-element
   git rev-parse --short HEAD
   npm ci
   npm run check
   npm run build:production
   ```

   `git rev-parse` 应至少包含交接提交 `0506b8d` 或更新提交。
3. 用微信开发者工具导入仓库根目录，不要新建模板项目，不要改用测试号 AppID。
4. 确认 `miniprogram/config.ts` 保持 CloudBase 环境与 HTTPS 登录地址；不要切回局域网 demo。
5. 重新生成预览二维码。二维码和预览信息写入被 Git 忽略的 `reports/mobile-test/`，不要提交二维码。
6. 手机完全退出此前预览，再扫描新二维码。记录错误括号中的分类码，并同时查看开发者工具 Console 和 Network。

## 下一步定位顺序

1. 先确认新预览能显示带括号的安全分类，避免继续根据旧包排障。
2. 在 CloudBase 控制台直接测试 `api`，输入 `{"action":"dashboard"}`。未携带客户端身份时应返回结构化 `UNAUTHENTICATED`，而不是运行时崩溃或 3 秒超时。
3. 查看 `api` 的监控请求次数、错误次数、耗时和请求 ID。日志服务当前未开启，不要为了排障擅自购买套餐。
4. 若分类为 `TIMEOUT`，重点检查 3 秒体验版上限和 `@cloudbase/manager-node` 冷启动/`ExecutePGSql` 耗时；先优化或拆分首页查询，再决定是否需要升级套餐。
5. 若为 `ACTION_FORBIDDEN`、`EXCEED_AUTHORITY` 或 `PERMISSION_DENIED`，继续核对“云函数安全规则”和 OPA 默认策略。只放行已登录、非匿名用户；业务函数内部身份校验必须保留。
6. 若为 `REQUEST_DOMAIN` 或 `NETWORK`，重新检查微信后台域名配置是否生效，并从真机调试 Network 获取实际失败域名；不要关闭域名校验绕过。
7. 若为其他平台错误码，按请求 ID 对照 CloudBase 监控和官方文档，不把原始 SDK 错误直接展示给用户。

## 云端与安全边界

- 不重建现有环境、数据库、函数或 `/login-ticket` 路由；先读取现状。
- AppSecret、自定义登录 JSON 私钥和 GitHub Token 均不得写入仓库、文档、命令历史或聊天。旧 AppSecret 和曾发到聊天的 GitHub Token 应在外部测试前撤销并轮换。
- 当前 PostgreSQL 是共享体验实例，没有内外网直连地址；业务函数通过短期云身份和 `ExecutePGSql` 访问。
- 数据库已创建业务表、RLS、版本表和原子写入函数；没有导入真实会员或收款数据。
- 不购买套餐、不开放公网服务、不关闭域名校验、不降低服务端身份校验。

## 故障修复后的手机验收

1. 新用户提交入会申请，管理员审核通过。
2. 管理员线下开私教和团课课包，核对余额与流水。
3. 学员预约私教：可用课时减 1、冻结加 1；教练端名单出现同一学员。
4. 学员取消：可用课时恢复、冻结归零；教练端状态同步。
5. 团课重复预约与取消流程，核对容量和名单。
6. 管理员停课，核对所有预约、冻结课时、名单和通知原子释放。

`npm run dev:demo` 和局域网 `/health` 仅作为离线回归备用，不是当前 CloudBase 真机链路。
