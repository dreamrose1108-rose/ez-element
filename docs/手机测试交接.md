## 家中接续步骤

1. 克隆或更新上述分支。先读 README、开发进度、验证记录和本说明。安装 Node.js/npm 及项目依赖：`npm ci`。
2. 检查或安装微信开发者工具 Nightly，优先使用其内置 `wechatide` 技能/CLI；从本机安装包读取技能及命令 `--help`，不要照抄另一台电脑的路径。登录、授权和安全开关由用户本人完成。当前项目基础库为 3.17.4。
3. 让手机和家中电脑处于能互访的局域网。检测电脑实际 LAN IPv4 地址。
4. 将 `miniprogram/config.ts` 中 `demoUrl` 改为 `http://家中电脑IP:4174/api`。当前值 `10.200.78.135` 是公司电脑地址，不能照用。保持 `mode: 'demo'`、空云环境。
5. 运行 `npm run check`，它会生成被 Git 忽略的小程序 JS 和云函数构建文件。只克隆而不构建无法直接运行。
6. PowerShell 启动演示服务：先设置 `$env:EZ_DEMO_HOST='家中电脑实际IP'`，再执行 `npm run dev:demo`，保持进程运行。其他系统使用对应的环境变量语法。未指定时默认只监听 127.0.0.1。
7. 电脑和手机浏览器分别访问 `http://家中电脑IP:4174/health`，预期为 `{"ok":true,"mode":"demo"}`。手机不通时先查 Wi-Fi 客户端隔离、网络路由和防火墙，不把它直接判为小程序错误，不关闭整个防火墙。
8. 导入仓库根目录到开发工具，确认演示数据加载成功，然后用 `create_preview_qrcode --help` 核对参数并重新生成预览二维码。旧二维码和旧预览包不能用于新地址验证。二维码不提交 Git。
9. 用户用具有测试号权限的微信扫码。若手机浏览器能访问而微信仍失败，依据新的请求错误详情检查微信本地网络权限、域名校验及真机调试设置，涉及权限操作请用户本人完成。
10. 验证学员七天选日期/多时段、私教预约与团课预约、冻结余额、教练名单同步、取消释放、管理员线下开卡与流水。出勤结算受实际课程结束时间限制，不绕过时间规则。

## 边界及排障记录

- 演示身份和数据均为虚构，角色可切换、没有正式鉴权；不把演示 API 直接暴露公网，不登记真实收款。重启服务会重置演示数据。
- 电脑休眠、服务退出、网络地址变化都会影响手机访问；地址变化后需重新构建和预览。
- 公司 Nightly 曾因基础库缓存重命名报 EXDEV 而白屏，补齐官方基础库缓存后解决。家中若出现白屏先查看当地日志，不预先修改安装文件或复制其他电脑登录凭据。
- 最近改动：`EZ_DEMO_HOST` 可选监听地址、`GET /health`、客户端 LAN 地址、展示实际请求失败信息、忽略临时二维码。
- 完整 V1 尚未完成，真实云端权限与并发、真机完整回归等仍待验证，详见开发进度。
