# 微信消课通知

## 当前范围

仅接入确认到课后的消课提醒。预约成功、取消、停课和课前提醒仍为站内消息或尚未接入微信，需另行提供适用模板。爽约不使用“课程完成”场景模板。

模板 ID：`uQw9Dwn6iRzjlcoCjSnvOlXeeHHAFrDJ8o3xfcnHWbg`，编号 1882，在线健身 / 消费成功通知。

| 微信字段 | 来源 |
|---|---|
| name1 | 课程名称，最多 10 个字符 |
| name2 | 授课教练姓名，最多 10 个字符 |
| date3 | 上课日期，UTC+8 |
| thing4 | 上课地点，最多 20 个字符 |
| thing5 | 课程类型、时间段、消课课时，最多 20 个字符 |

该模板没有金额或余额字段；完整扣款及余额继续显示在站内消课记录。消息跳转至学员消息页。

## 身份与发送

学员在“消息 → 订阅消课提醒”主动调用微信订阅授权。接受后用新的 wx.login code 调用既有登录网关，服务端通过 jscode2session 取得真实 OpenID；仅绑定对应已审核学员。不接收客户端传入的 OpenID、目标学员 ID 或模板内容。订阅状态不是无限额度，最终发送资格以微信返回结果为准。

收件人信息保存在 users 记录的 receiptRecipient 字段，仅服务端使用。dashboard 的 profile/users 均移除该字段。旧数据无需迁移，未绑定学员显示“需先订阅”。

结算事务同时把 pending 状态写入原站内通知，使用同一确定性通知 ID。事务提交成功后，小程序通过独立请求调用 getLoginTicket 的已鉴权 sendReceipt 分支。仅管理员或该场次教练能调用，收件人、课程和模板数据全部从服务端读取。若客户端在两次请求之间关闭，任务保留 pending，工作人员可在授课卡片重试；此版没有后台定时队列，不保证离线自动补发。

发送前事务领取任务；sent 不再发送，明确失败可重试。发送后超时或结果无法确认标记 unknown，避免自动重发。进程在发送中被平台终止可能保留 sending，需人工核对微信端送达情况。所有发送失败都不撤销结算，也不再次扣费。

## 部署要求

1. getLoginTicket 当前超时实测为 3 秒，需要调整为至少 15 秒再部署通知版本。若套餐限制不可修改，先处理运行时限制；不自动付费升级。
2. getLoginTicket 复用已有 EZ_APP_ID、EZ_WX_APP_SECRET、EZ_ENV_ID 和登录凭据，不将密钥写入仓库。新增 PostgreSQL 管理 SDK 依赖，须完整部署并远程安装依赖；该函数执行身份需要与 api 相同的数据库运行权限。
3. EZ_NOTIFICATION_STATE 默认 developer；体验版使用 trial，正式发布前设置 formal。
4. 微信获取 access_token 接口如要求服务器 IP 白名单，需按实际错误配置微信后台；不能用开放所有 IP 的方式绕过。
5. 顺序：先更新 getLoginTicket 并验证普通登录仍工作，再更新 api，最后刷新/预览小程序。
6. 真机以学员身份主动订阅，由管理员确认一条真实已完成课程，核对微信到达、站内扣费记录及重复操作不重复推送。未执行真实扣费或测试发送前，不宣称真机端到端通过。

目前只完成本地实现和模拟测试；上线结果以验证记录为准。
