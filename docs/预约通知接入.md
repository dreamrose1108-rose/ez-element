# 预约与开课通知

2026-10-29 接入预约成功、预约取消、课前两小时提醒，原有消课通知保留。

模板与字段以 `server/booking-notification.ts` 为准。学生在消息页点击“订阅预约与上课提醒”申请三类一次性订阅，消课通知单独申请。部分同意会显示同意数量；拒绝不影响业务。身份绑定沿用服务端校验微信登录码的流程，OpenID 不返回客户端。

预约和取消事务将任务写入现有 inbox JSONB，同事务失败会一起回滚。学员取消、管理员整场停课均通知学员。门店停课保留原因。不向未订阅的教练扩大发送。

`getLoginTicket` 的 `booking-notifications` 定时触发器每分钟运行（`0 * * * * * *`），最多领取 8 个到期任务。成功/取消通常下一分钟发送，积压时顺延；课前提醒在两小时前进入到期队列，不足两小时预约立即进入队列。未来任务不会占用查询批次。函数超时为 60 秒，既有登录路由不变。

发送前校验学员状态、预约状态、场次和当前时间，取消或已开课不再提醒。领取与状态变更使用存储事务，并发执行不重复领取。已发送不重发；明确失败记 failed，拒收记 needs_subscription；结果丢失记 unknown，不自动重发。领取后函数退出的 sending 状态超过一分钟转 unknown。发送开始后再取消，已发出的微信通知无法撤回。

每种模板都需微信侧可用订阅次数，身份绑定不代表永久授权。通知失败不回滚预约或余额。未实现微信失败任务的自动重试和历史预约提醒补录，只有接入后的新预约入队。

验证：自动化覆盖字段映射、两小时边界、并发防重复、取消/停课、已开课、无授权、超时和未来任务积压；云端空队列调用返回成功，未制造真实预约或发送测试消息。真机订阅及实际收信仍须验证。
